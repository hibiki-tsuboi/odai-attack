# OdaiAttack — Claude Code 用プロンプト集

Xcode で作成済みの `OdaiAttack`（SwiftUI）プロジェクトのフォルダで Claude Code を起動し、上から順に貼り付けて使う想定です。
1つのフェーズが終わって実機で動作確認できてから、次のフェーズに進んでください。

---

## 0. 事前準備（ターミナルで実行）

TypeSafe 公式の Claude Code プラグインを入れておくと、Jev API の正しい使い方を Claude が参照できます。

```
claude plugin marketplace add typesafe-ai/skills
claude plugin install typesafe@typesafe-ai
```

API キーは https://console.typesafe.ai で発行しておきます。

---

## 1. 最初に渡すプロジェクト概要（CLAUDE.md の作成）

```
このリポジトリは Xcode で作成した SwiftUI の iOS アプリ「OdaiAttack」です。
以下の内容で CLAUDE.md を作成してください。今後の作業はすべてこの方針に従ってください。

## アプリ概要
- お題（例:「赤いもの」「冬に使うもの」）に対して、制限時間10秒でお題に合う言葉をできるだけ多く声で言うパーティーゲーム。
- iPhone の音声認識で言葉を1語ずつ拾い、TypeSafe AI の Jev モデルで即座に判定する。
- 判定の速さがゲームのテンポそのものなので、レイテンシを最優先で扱う。

## Jev について
- Jev は文章を生成しない「System One」モデル。状態（テキストや JSON）と型付きの質問を送ると、型付きの答えと確率を返す。
- 質問タイプは Choice / Score / Noul。Noul は「この文は真か？」に対して true の確率（0〜1）を返す。
- 公式 SDK は Python と JavaScript のみなので、Swift からは REST API を URLSession で直接呼ぶ。
- リクエスト/レスポンスの正確な形式は推測せず、typesafe プラグインのスキルか https://docs.typesafe.ai を必ず確認してから実装すること。
- モデルはバージョンを固定する（jev-latest は新リリースで答えが変わるため）。現時点では jev-1.13.0 を想定。ドキュメントで最新の固定版名を確認すること。
- Jev は渡された状態以外の世界知識を持たない。判定に必要な情報（お題、候補の言葉、判定基準）はすべてリクエストに含める。

## 設計方針
- SwiftUI + Swift Concurrency (async/await)。
- Jev の呼び出しは `JevClient` プロトコルの裏に隠し、実装を差し替え可能にする。
  - 現在: TypeSafe API を直接呼ぶ実装（開発用）
  - 将来: 自前の中継サーバー（Cloudflare Workers 想定）経由の実装に差し替える
- API キーはソースコードに直接書かない。`Secrets.xcconfig`（.gitignore 対象）から Info.plist 経由で読み込む。
- 通信にかかった時間（ms）を毎回計測してログに出す。
- 外部ライブラリは極力使わない。
```

## 2. フェーズ1: テキストで判定して速度を測る画面

```
CLAUDE.md の方針に従って、まず検証用の画面を作ってください。

## 作るもの
- お題を入力するテキストフィールド
- 言葉を入力するテキストフィールドと「判定」ボタン
- Jev に以下の2つの質問を1リクエストでまとめて送る
  - Noul: この言葉はお題に当てはまるか
  - Score: この言葉はどれくらいお題らしいか（典型的か）
- 結果表示: Noul の確率、Score の値、通信にかかった時間（ms）
- 判定履歴をリストで表示（言葉 / Noul / Score / ms）
- 同じお題と言葉で10回連続判定して、レイテンシの最小・平均・最大を出すボタン

## 注意
- API の形式は必ずドキュメントで確認してから実装する。
- Secrets.xcconfig の作り方と、Xcode 側での設定手順（Configuration への割り当てなど）を最後に説明してください。
- 実装後、ビルドが通ることを確認してください。
```

## 3. フェーズ2: 音声認識をつなぐ

```
フェーズ1の判定処理を使って、声で言った言葉を判定できるようにしてください。

## 作るもの
- マイクボタンを押すと音声認識（日本語）を開始・停止
- 認識途中の文字列から「1語」を切り出して、確定した語ごとに Jev で判定
  - iPhone の音声認識は単語ごとではなく、認識途中の文字列を更新しながら返してくるので、区切りのロジックが必要
  - 例: 前回確定した部分からの差分を新しい語とみなす／一定時間（例: 0.4秒）更新がなければ確定、など
  - 区切りのパラメータは後で調整しやすいように定数にまとめる
- 同じ言葉の重複は判定しない
- 画面に「認識中の文字列」「確定した語と判定結果」をリアルタイム表示

## 注意
- プロジェクトの Deployment Target を確認し、利用できる最新の音声認識 API を選んでください。どの API を使ったか理由も説明してください。
- Info.plist にマイクと音声認識の利用目的の説明を追加してください（日本語で）。
- 判定リクエストは並行して飛ばしてよいが、結果は言った順に表示する。
```

## 4. フェーズ3: ゲームにする

```
フェーズ2の仕組みを使って、ゲームとして遊べるようにしてください。

## ゲームの流れ
1. タイトル画面 → スタート
2. お題を表示し、3・2・1のカウントダウン
3. 10秒間、声で言葉を言う
   - お題に合っていれば（Noul がしきい値以上）正解音「ピコン」と +1点
   - Score が高い言葉は小さく、意外性のある言葉（Noul は高いが Score が低い）はボーナス点
   - 不正解は短いブッという音
4. 終了画面: 得点、言った言葉の一覧（正解/不正解、確率）

## その他
- お題はまずアプリ内に20個ほど用意（家族や友達で遊べる一般的なもの）
- 正解判定のしきい値や点数ルールは定数にまとめて調整しやすくする
- 残り時間は大きく、正解時は画面が一瞬光るなど、テンポが伝わる演出を入れる
- 効果音はシステムサウンドか、コードで生成した短い音で代用してよい
```

## 5. 後で使う: 中継サーバーへの切り替え

```
TestFlight 配布に向けて、API キーをアプリに含めない構成にしたいです。

- Cloudflare Workers で Jev API を中継するサーバーを作成（別フォルダ `proxy/` に）
- アプリ側は `JevClient` の中継サーバー版の実装を追加し、切り替える
- 中継サーバー側でリクエストの内容を最低限チェックし、想定外の使われ方を防ぐ
- デプロイ手順と、API キーを Workers の Secret に登録する手順を説明してください
```
